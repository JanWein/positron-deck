01 / GET STARTED

Two installs.
One familiar workspace.

The companion sends keyboard shortcuts from Windows. The IDE extension resolves them into native commands beside your project, even when that project lives in Workbench.

1

Inside Positron

Download positron-deck-0.2.0.vsix from the release. Open Extensions → ⋯ → Install from VSIX. In Workbench, install inside your remote Positron session.

Open the Command Palette and run Positron Deck: Open Terminal to verify the extension.

2

On your Windows PC

Download org.positron-deck.shortcuts.streamDeckPlugin and double-click it. In Stream Deck 7.1+, open the Positron Deck category and drag actions onto buttons.

Keep the intended IDE window or Workbench tab in the foreground.

Your existing buttons keep working. Version 0.2 preserves the original 32 action IDs and default hotkeys. Update both packages together to use the expanded catalog.

How a button becomes an action

  1. PressStream Deck button
  2. SendLocal Windows hotkey
  3. ResolvePositron keybinding
  4. RunNative IDE command

There is no direct socket, API, credential exchange or network bridge to the IDE. The Elgato SDK uses its normal local connection to the Stream Deck application. A button cannot report Git status, runtime state or test results back from Positron.

03 / WORKFLOWS

Make the small
steps work together.

Recipes run inside the IDE. They respect save cancellation, stop on errors and can wait for a finite task to succeed. Eight dedicated buttons are available for your own recipes.

Save the active script, then run it in the matching interpreter. Your editor and runtime stay connected.

04 / WRITE

Save → Layout → Preview

Prepare a Quarto workspace and launch preview. Native preview stays in control of the running process.

positronDeck.quartoWorkspace

Also included: Format and Save, Save and Test, a workflow chooser, and eight named custom slots. These recipes are design proposals inspired by the documented Positron workflows; they are not usage rankings.

A quality gate that really waits

Define finite VS Code tasks named Tests and Check. Add the following to your workspace settings. The deployment step is reached only if both tasks exit successfully.

{
  "positronDeck.workflows": [{
    "name": "Validate and deploy",
    "steps": [
      { "save": "all" },
      { "task": "Tests" },
      { "task": "Check" },
      { "command": "positronDeck.deploy" }
    ]
  }],
  "positronDeck.workflowSlots": ["Validate and deploy"]
}

Assign Custom Workflow 1 to a button. Custom workflows always show their steps for confirmation; deployment keeps its own provider confirmation. A step can be a Deck command, a native command with an args array, a save, or a named task. Maximum: 32 steps. Nested workflows and background-task gates are rejected.

Dispatch is not completion. Native test commands, runtime execution and preview may return while work continues. Use a task step for a checked completion gate. Never chain deployment behind a simple test-dispatch command and assume tests passed.

05 / CONFIGURATION

Generic by design.
Personal by configuration.

Open Settings and search positronDeck. No server, repository, branch, Connect instance or credentials are built in.

SettingDefaultPurpose

Hotkey mapping

The original 32 commands keep their F13–F24 combinations. New actions use a two-stroke chord: Ctrl+Alt+Shift+F1 through F5, followed by a letter or digit. The plugin sends both strokes and aborts the second if the foreground window changes. This is a focus check, not a guarantee that the focused window is Positron.

Every button can use the default, alternative mapping or a custom shortcut/chord. Import the supplied alternative keybindings by merging them into your existing user keybindings array. Do not replace unrelated shortcuts. Windows keyboard layouts and browser interception still need a local test.

To use Deck shortcuts while the terminal is focused, run Enable Hotkeys in Terminal. It asks before adding Deck commands to your user-level terminal.integrated.commandsToSkipShell. Changing settings does not send any keystrokes.

available where.

EnvironmentSupported behavior
Windows 10+ x64 / ARM64Stream Deck companion with local SendInput. Stream Deck application 7.1+.
Positron DesktopPrimary target. Native features depend on version and enabled views.
Positron Pro / WorkbenchExtension in the remote session, companion on the local Windows machine. Browser focus and hotkey delivery require local validation.
VS Code 1.96+Generic editor, layout, navigation, Git and task commands. R/Python and Quarto require their providers. Positron-only commands explain when unavailable.
macOS / LinuxThe IDE extension can be used through the Command Palette or manual keybindings. The Stream Deck companion is Windows-only.
Restricted workspacesNavigation remains available. Code, workflows and project mutations require trust.

R package actions require devtools, styler or lintr as appropriate; packages are never installed automatically. Apps support R Shiny, Python Shiny, Streamlit and FastAPI. Deployment supports Posit Publisher, Git push, VS Code tasks or a custom shell command.

Validation boundary. Automated host mocks verify delegation, safeguards and workflow behavior. Windows input encoding and the Elgato protocol are tested separately. Real Windows hardware, graphical Positron and Workbench end-to-end behavior still require local acceptance.

07 / TROUBLESHOOTING

Find the missing link.

A button does nothing

First run the same Positron Deck command from the IDE Command Palette. If that works, check the foreground window and browser tab, matching package versions, duplicate keybindings and the button's selected mode. Use Keyboard Shortcuts Troubleshooting in the IDE to inspect received keys.

A shortcut types a letter into the editor

The first stroke of a chord was not received. Check the IDE keybinding, then try the button's alternative or custom mode. Use the same mapping on both sides. Keep physical Ctrl, Alt, Shift and Windows keys released when pressing the Deck.

Data Connections, Packages or a notebook action is unavailable

These actions depend on Positron features, version and active context. Run Check Action Availability. Enable the relevant view or extension; notebook actions require the Positron notebook editor, data actions an active Data Explorer, and language actions a supported source file.

The terminal receives the shortcut

Run Enable Hotkeys in Terminal and approve its user setting update, or manually add selected Deck command IDs to terminal.integrated.commandsToSkipShell.

The button shows an alert

The companion could not send the complete input sequence. Physical modifiers may be held, the focused window may have changed, or Windows may block input across elevation levels. Run Stream Deck and Positron at the same normal privilege level. Plugin feedback does not report IDE success.

A workflow stops or keeps waiting

Review the native task output. Task gates need an exact, unambiguous label and a finite process with a zero exit code. Background tasks are refused. Stop a hung task through the IDE task controls; remaining steps will not run.

Where are errors and diagnostics?

Run Positron Deck: Show Log for action lifecycle logs. Run Check Action Availability for a local text report of registered native commands. Code, secrets and raw provider errors are excluded from the Deck log.

08 / BUILD & CONTRIBUTE

Small pieces.
Open possibilities.

TypeScript, the VS Code API, an optional Positron adapter and the Elgato SDK. The source lives together in one MIT-licensed repository.

git clone https://github.com/JanWein/positron-deck.git
cd positron-deck
npm --prefix extension ci
npm --prefix streamdeck ci
npm run generate
npm run lint
npm test
npm run package

Use Node 24+. Edit catalog/actions.json for metadata and delegated actions. The generator updates both manifests, bindings, icons and documentation. Project-aware logic stays in provider modules; native commands are checked before execution.

GitHub Actions validates both packages and publishes installation artifacts. GitHub Pages serves this static documentation. A release is built from the source, not from an unverified local dependency tree.
